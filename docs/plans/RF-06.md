# RF-06 — Onboarding y ayuda

**Source PRD:** [docs/prds/PRD-cookie-bakery.md](../prds/PRD-cookie-bakery.md) §3 RF-06
**Status:** in progress

## Statement

> ### RF-06 · Onboarding y ayuda
> - Página/modal "Cómo empezar": instalar Nightly, añadir Cookie Chain (RPC), conseguir COOK vía bridge, volver a la app. Enlaces a docs oficiales.
> - Estado vacío en cada pantalla explicando el siguiente paso.
> - Footer con links: repo GitHub, CookieScan, docs de Cookie Chain, bridge, Telegram.

## Acceptance criteria

- **AC-06.1** — Un usuario sin contexto entiende qué hacer en menos de 1 minuto (revisión manual con alguien ajeno al proyecto).
- **AC-06.2** — "Cómo empezar" cubre los cuatro pasos en orden: instalar Nightly → añadir Cookie Chain → conseguir COOK → volver.
- **AC-06.3** — Cada pantalla (Bake, Airdrop, Oven) tiene un estado vacío que nombra la acción siguiente y enlaza a ella.
- **AC-06.4** — El footer enlaza a repo, CookieScan, docs de Cookie Chain, bridge y Telegram; todos los links abren en pestaña nueva con `rel="noreferrer"`.
- **AC-06.5** — El modal se abre desde el header en cualquier pantalla y se cierra con Escape, clic fuera y botón, devolviendo el foco al disparador.

## Dependencies

- **RF-01** — el estado vacío de "sin wallet" ya lo entrega RF-01.8; aquí se generaliza al resto de pantallas.
- **RF-02, RF-03, RF-04** — deben existir las pantallas para poder darles estado vacío. Es el motivo de que esto sea fase 5.
- Datos de red de `src/lib/chain/config.ts` (RF-01.2) para mostrar el RPC a añadir en Nightly.

## Reuse (do not reinvent)

- `src/components/NoWalletEmptyState.tsx` (RF-01.8) — refactorizar para que use el `EmptyState` genérico de RF-06.2, no mantener dos.
- `src/lib/chain/config.ts` (RF-01.2) para el RPC y las URLs; el modal no debe repetir literales.
- Tokens de color de `src/index.css`; el contraste AA se ajusta ahí, no por componente.

## Out of scope

- Framework de i18n (PRD §4: solo inglés en v1).
- Tour interactivo o tooltips paso a paso.
- Vídeo o GIF incrustado en la app — las capturas van al README (RF-07).
- Diseño mobile-first (PRD §1.5: responsive básico basta).

## Open risks

- **AC-06.1 es subjetiva por definición** ("menos de 1 minuto", revisión manual). No se puede automatizar: el criterio operativo es que una persona ajena al proyecto complete "conectar → crear token" sin preguntar nada. Reservar tiempo real para esa prueba antes de la submission.
- El paso "añadir Cookie Chain" depende de cómo Nightly gestione redes personalizadas, que no está verificado. Si Nightly no permite añadir un RPC arbitrario, este paso hay que reescribirlo con lo que se aprenda en el spike de fase 1.
